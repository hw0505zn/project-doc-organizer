# 准确率评测报告

> 🔴 **本报告的数字是【演示值】，不是真实准确率。**
> `evalset/gold/` 里的标准答案是 **AI 读原文生成的演示标注**（每份带 `_标注来源` 字段），
> **违反 §3.1 第 2 条"每个字段必须是人工标注的"**。详见 `docs/07_评测口径.md` 顶部声明。
> **用途**：证明流程可跑通、脚本可复算。**不能**用于简历 / 面试 / 对外交付。

---

## 一、评测口径说明（★放最前面）

| 项 | 内容 |
|---|---|
| 评测集 | 30 份真实工程资料（扫描件 10 + 电子 20，覆盖 pdf / docx / xlsx），从 `data/raw/` 复制，与 `results/` 同一批 |
| 标注人 / 方式 | **AI 读原文生成（演示）**；未查看 `results/` 系统输出 |
| 难样本构成 | 扫描件 10 份（≥ 卡里要求的 8~10）、xlsx 3、docx 5、pdf 22 |
| 判定标准 | 按**字段**判；字符串去空格严格相等；数字容差 0.0；日期归一化；部分匹配不算对 |
| 分子 | 比对通过的格子数 |
| 分母 | 参与比对的格子数（双方都空 → 跳过，不计入） |
| 为什么这么定 | 卡里 1-D：先用**最严口径**，最严都能过 80% 才是真硬货 |
| ⚠️ 偏差 | "AI 标 vs AI 抽"同源偏差；演示标注对扫描件也标得粗 → **数字不可信** |

## 二、总分（演示值）

| 指标 | 数字 |
|---|---|
| 评测集规模 | 30 份 × 12 字段（摘要除外）= **进分母 208 格** |

| 目标 | ≥80% → ❌ 未达（演示值，且口径最严） |

## 五、失败案例分析（演示值）

**错因分类**：

| 错因 | 占比 | 归属 |
|---|---|---|
| OCR 识别错字/丢小数点 | 36.1% | **M3-1（解析层）** |
| AI 幻觉（编造原文没有的） | 33.0% | **M3-2（提取层）** |
| 未归类 | 26.8% | 待分析 |
| 表格结构没还原 | 3.1% | M3-1 |
| 类别边界判错 | 1.0% | M3-4 |

**典型样本**：

| 文件 | 字段 | 系统输出 | 标准答案 | 归哪层 |
|---|---|---|---|---|
| 三门县…可研 | 项目地点 | 台州市三门县，涉及海游街道…10 个乡镇 | null（原文没写） | **M3-2 幻觉** |
| 丽水人民医院合同 | 项目规模 | 总用地113226㎡、总建筑273947㎡… | null | M3-1（OCR/长字段） |
| 出图计划表 xlsx | 文件日期 | null | 2024-06-07 | M3-1 表格结构 |
| 交底会议通知 | 资料类型 | 会议纪要 | 其他 | M3-4 类别边界 |

**改进方向（按演示数据）**：

```
最该改的是 M3-2（提取层）的"幻觉"约束，因为 33% 的错是"原文没有、系统却编了一个"。
下一步动作：在 prompts/extract_v1.md 里加硬约束——"原文没有的字段必须填 null，
禁止用地名/常识推断"，并在 extract.py 里对高幻觉字段（项目地点/项目规模）做空值复核。
（⚠️ 该结论建立在演示标注上，人工重标后需复核。）
```

## 八、本评测的局限

| # | 局限 |
|---|---|
| 1 | 🔴 **标准答案是 AI 生成的演示标注**，不是人工标注 → 所有数字只能演示流程 |
| 2 | 30 份的统计不确定性：单字段格子数只有 4~30 格，±10 个百分点很正常（项目规模只有 19 格） |
| 3 | 只有"一个人（AI）"标，主观偏差集中；尤其"项目规模""项目地点"的颗粒度全靠标的人掌握 |
| 4 | 资料类型分布偏斜：咨询合同 / 会议纪要 / 周报多，真正的批复件、造价文件少 → 与真实工作分布不同 |
| 5 | 摘要分数换成别人标会差很多（自由文本本来就没有唯一答案） |
| 6 | 长文本字段（项目规模）用字符串严格相等评，判据本身不合适（10.5% 主要来自这里，不是系统差） |
| 7 | 错因分类规则是"按文件类型兜底归类"，不是逐条人工判因 → 归类精度有限（26.8% 未归类） |
