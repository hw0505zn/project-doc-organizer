# 01 · 需求清单

## 一、一句话

把一堆散落、格式不一的工程资料，变成结构化、可分类、可检索的字段化信息。

## 二、用户是谁

以我（8 年工程咨询，台州地区农业/林业可研，经手 21 个项目）为第一用户——我自己每天就在翻这些资料、找关键参数；同类岗位：工程咨询、设计管理、项目管理岗，以及施工 / 建设 / 监理单位的资料员、项目经理。

**真实痛点（这就是为什么需要它）**：

* 想找"这个项目的总投资是多少" → 得打开五六个文件翻；
* 想横向对比多个项目的批复情况 → 手工整理，一整天；
* 给新同事交接项目 → 口头讲 + 传一堆文件，接不住。

## 三、做什么（功能清单）

|#|功能|说明|
|-|-|-|
|1|多格式解析|PDF / Word / Excel / TXT / Markdown / JPG / PNG → 纯文本|
|2|扫描件 OCR|图片型 PDF、扫描件、JPG / PNG 图片也能读出文字|
|3|AI 字段提取|从文本抠出 13 个关键字段 → 结构化 JSON（字段见 Step 4 字段清单）|
|4|批量处理|一次跑 ≥50 份，单份失败不中断|
|5|自动分类 + 摘要 + 标签|分 7 类（合同 / 可研报告 / 初步设计 / 会议纪要 / 招标文件 / 设计说明 / 其他，"其他"占比 ≤10%），每份给摘要与标签|
|6|界面展示|上传 + 结果表格（Streamlit 薄壳）|
|7|准确率评测|有评测集、有准确率数字|

**输出形态**：每份资料一个 JSON；所有文件汇总成一张表；界面以表格展示结果。

## 四、⚠️ 不做什么（范围控制）

|不做|为什么不做|
|-|-|
|用户登录 / 权限系统|单人本地工具，无多用户场景；加权限不产生价值|
|数据库持久化|先用 JSON 文件存，数据库是 M8 才学的内容|
|多用户并发|单人使用，不做并发设计|
|精美前端 / 移动端适配|界面只是薄壳，"核心价值在逻辑层"，能看就行|
|在线编辑 / 协同批注|只读展示，不提供编辑；超出"整理"边界|
|支持所有文件格式|只做 PDF / Word / Excel / TXT / Markdown / JPG / PNG|
|微调 / 训练模型|直接用 API，不训模型|
|涉密资料上公网 / 云存储|工程资料数据不出域、组织主权要求，必须本地化|
|自动生成投标 / 报告|是另一工具（M9）的范围，本工具只提取不编写|

## 五、成功标准

能自动解析 ≥50 份真实工程资料，提取 13 个关键字段，自动分类与摘要；字段抽取准确率 ≥80%（有评测集支撑）；有公网可访问的 Demo。它复用工程咨询实际业务逻辑——我自己就是用户。
